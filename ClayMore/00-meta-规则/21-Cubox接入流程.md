# Cubox 接入流程

`Cubox/` 是外部软件同步目录，作为 external raw source 处理。

## 触发词和边界

| 用户说法                        | 默认动作                                                      |
| --------------------------- | --------------------------------------------------------- |
| “整理 Cubox”“更新 Cubox”“整理资料”“更新资料”“整理最新资料”“更新最新资料” | 触发完整流程：先从 `Cubox/` 提取到 raw，再基于 raw 分析并沉淀到 wiki；同步索引、汇总、资料脑图、公司名频率表和整理报告 |


## 硬规则

- 不直接移动、重命名或删除 `Cubox/` 中的文件。
- 每次触发整理或更新 Cubox 资料时，先做快速增量索引：扫描 `Cubox/` 的文件名、frontmatter、URL、标题、大小、修改时间，并与 `80-raw-原始资料/Cubox/`、`Wiki/` 资料流、索引、汇总页和最近整理日志对照，标出新增、变化、已处理和跳过项。
- 只对新增、变化或已提取但未沉淀 wiki 的 Cubox 资料走全流程；已处理且无变化的资料不重复复制、转写或沉淀。
- 从 `Cubox/` 生成的 raw 副本、metadata、转写稿和提取模板都必须放在 `80-raw-原始资料/Cubox/` 下对应分类。
- 先解析 frontmatter `tags`，再判断分类。
- 可映射标签优先；标题、URL、正文关键词只能兜底。
- 标签与标题/内容冲突时，按标签归档，并在报告中标记冲突。
- 标签无法映射时，不自行创建新目录；写入报告并询问用户。
- 网页和视频资料需要按 [[00-meta-规则/22-内容提取流程]] 标记内容质量。
- 除非用户明确说“只提取 / 只入库 / 只建索引 / 先轻量整理”，不得只生成 raw、metadata、notes_template 或索引；需要继续沉淀到对应 wiki 候选页、主题页或说明为什么不进入 wiki。
- `_notes_template.md` 不是整理完成态。模板中如果仍有 `TODO:`，该条必须标记为“已提取但未编译”；已有 `_transcript.md` 的，继续基于转写稿生成 wiki 候选页/主题页和资料脑图；没有 `_transcript.md` 的，标为 `metadata-only / 待转写 / 待核验`，不得伪装成已整理内容。

## 敏感性

| 类型 | 处理方式 |
|---|---|
| 低敏公开资料 | 可以进入主库 |
| 股票、财务、健康、法律资料 | 可以索引和摘要，标注来源和不确定性 |
| 保单、证件、账号、身份资料 | 只做低敏索引，不写密码、密钥、完整证件号 |
| 无法判断敏感性 | 跳过，写入整理报告 |

## raw 副本

raw 副本保留：

- Cubox 原路径。
- 原文件名。
- 新生成的 raw 副本、索引条目、wiki 沉淀页和资料脑图入口标题默认加日期前缀，格式为 `YYYY-MM-DD - 标题`；日期优先取来源发布日期，缺失时取 Cubox 文件日期或整理日期。
- 来源 URL。
- 收藏日期或文件日期。
- 来源发布日期；无法确认时写“来源日期未知”。
- 原始 tags。
- 摘要、正文摘录或内容质量标记。

## 整理报告

每批 Cubox 报告必须包含：

- 本次范围。
- 增量索引：新增、变化、已处理、跳过项；无新增时写“无新增”。
- 分类审计表。
- 处理追踪表：Cubox 原文件 → raw 副本 → wiki 页面 → 状态。提取模式下 wiki 页面可留空，并标记“已复制 raw”或“已提取 raw”。
- 编译状态表：metadata、transcript、notes_template、wiki 页面、资料脑图、公司名频率表分别是否存在；`notes_template` 含 `TODO:` 时必须列为未编译。
- 处理结果。
- 待核验事项。
- 待确认事项。

状态字段固定为：未处理 / 已复制 raw / 已提取 raw / 已沉淀 wiki / 已跳过。

## wiki 沉淀资料脑图

当 Cubox raw 被沉淀为独立 wiki 页面时，默认同步生成资料脑图：

- 默认使用 Advanced Canvas 兼容的 Obsidian `.canvas` JSON；脑图放在对应 wiki 页面同目录，命名为 `原页面标题-资料脑图.canvas`。
- 资料脑图必须基于该页面和其 raw 来源单独生成，不得使用统一占位模板，也不得只写“资料摘要、关系图主线、内容节点”等通用占位文字。
- 脑图必须围绕该页面的核心问题或主题组织，采用中心主题向外发散的结构；优先包含来源、背景、核心概念、技术/业务环节、公司或对象线索、待核验问题、下一步行动。
- Advanced Canvas 脑图应尽量使用 `styleAttributes` 表达节点形状、边样式、虚线待核验或风险节点；仍必须保持 Obsidian Canvas JSON 合法。
- 股票、财务、健康、法律类资料的脑图必须显式标注低置信、待核验和非建议口径，不得把社媒声称画成确定事实。
- Canvas 文件必须是合法 JSON，包含 `nodes` 和 `edges`；节点优先使用 text/file 类型，file 节点链接回来源 wiki 页面。
- 生成后必须解析 Canvas 结构校验：节点数不能为 0；边引用的 `fromNode`/`toNode` 必须都存在；`x/y/width/height` 必须是 number，画布边界不得出现数千以上的异常坐标。
- 生成或更新资料脑图后，必须从对应 wiki 页面、索引页、汇总页或整理报告增加入口；暂无脑图时用 `-` 占位，不要链接不存在的页面。
- 单篇资料不再默认生成 `原页面标题-关系图.canvas`、`原页面标题-候选关系图.canvas` 或 `原页面标题-思维导图.canvas`；历史单篇关系图/候选关系图/思维导图应迁移或替换为 `资料脑图.canvas`。

## 股票资料脑图和频率表

处理 `Cubox/` 股票资料并生成资料脑图时：

- 默认使用 Advanced Canvas 兼容的 Obsidian `.canvas` JSON，脑图放在对应详细报告同目录，命名为 `原报告标题-资料脑图.canvas`。
- 资料脑图必须基于该资料正文逐篇生成，禁止套用统一占位模板；节点只整理来源、主题、产业链环节、公司/标的、工具模块、业务链条、关键关系和待核验点。
- Canvas 节点应短句化，优先写“环节 + 公司/标的 + 关系/待核验点”；不得写大段研究说明。
- Canvas 文件必须是合法 JSON，包含 `nodes` 和 `edges`；节点优先使用 text/file 类型，file 节点链接回来源详细报告。
- 生成后必须解析 Canvas 结构校验：节点数不能为 0；边引用的 `fromNode`/`toNode` 必须都存在；`x/y/width/height` 必须是 number，画布边界不得出现数千以上的异常坐标。
- Excalidraw 不再作为默认格式；仅在用户明确要求手绘展示图时使用。
- 资料脑图必须标注来源详细报告、低置信/待核验口径。
- 股票视频字幕、OCR 或资料正文中抽取出的公司名，若存在识别不确定、同音词、错别字或简称混淆，优先用本地持仓/自选匹配，再用 `Wiki/10-股票投资/02-股票研究流/基础数据/A股公司名称库.csv` 校验证券简称、代码和市场；名称库可通过 `python .\Tools-工具\update_a_stock_name_library.py` 刷新。
- 股票资料中出现“疑似公司名”时，不得直接长期保留笼统“疑似”状态；必须先做公司名称库校验：命中时写规范简称、代码和市场，并保留 ASR/原文写法说明；近似命中时写“命中近似”；未命中时才标记“本地名称库未命中 / 疑似 ASR 错字 / 需回视频画面或外部资料复核”。
- 材料名、技术名、产品名、客户名或机构名不得因为出现在“相关公司”列就默认当作上市公司；本地名称库未按公司名命中的对象，应标明“材料类别 / 技术术语 / 客户对象 / 非上市公司线索”等状态。
- 本地名称库、东方财富行情接口或交易所公开列表只作为公司名/证券简称校验层，不用于确认供应链关系、客户、订单、份额、业绩、机构持仓或投资结论；公司名命中后，相关产品、客户、份额、订单和业绩仍必须保留“待核验”，除非已回到公告、财报、研报或可信公开资料验证。
- 股票公司显示规范：新建或更新股票资料的 wiki 页面、表格和资料脑图时，凡是已识别为上市公司或待核验股票公司的名称，统一用黄色字体标识；股票代码不改色。Markdown 优先写为 `<span style="color:#d6a100">公司名</span>（代码）`，Canvas text 节点写入 JSON 字符串时必须使用可解析写法，例如 `<span style='color:#d6a100'>公司名</span>（代码）` 或正确转义双引号；代码可缺省但公司名必须上色。不要修改 raw 原文、转写稿原文、代码块、URL、文件路径或 Obsidian 链接目标；如黄色在当前主题下不可读，可换用更清晰的黄色系但仍保持“股票公司=黄色”的视觉规则。
- 跨资料、跨主题的核验池和公司名/代码校验结果统一放入 `Wiki/10-股票投资/01-Cubox资料流/待核验/`；专题内 P0/P1 事实核验表保留在对应专题目录。
- 生成或更新资料脑图后，必须同步更新 `Wiki/10-股票投资/01-Cubox资料流/股票资料汇总.md` 的 `资料脑图` 或对应说明列。
- 暂无资料脑图的资料在汇总页中用 `-` 占位，不要链接不存在的页面。
- 只要新增、更新、改名或移动股票资料沉淀页、资料脑图、核验表、主题框架页、公司名标黄或 raw 索引，就必须在同一轮同步检查并更新 `Wiki/10-股票投资/01-Cubox资料流/股票资料汇总.md`：更新日期、状态面板、主题表、资料脑图链接和 metadata-only 状态。
- 只要股票资料正文页或公司名标黄发生变化，就必须同步重算并更新 `Wiki/10-股票投资/01-Cubox资料流/公司名出现频率总表.md`；资料脑图生成或更新本身不触发该表重算。统计范围只包含 `01-Cubox资料流` 下已标黄的公司名；只统计 Markdown 资料正文/报告页，排除 `.canvas`、关系图、候选关系图、思维导图、资料脑图、`股票资料汇总.md` 和本页；顶部“快速浏览”必须用横向多列表，默认展示前 30 个高频公司，5 列 × 6 行，每项写为 `公司名×出现次数`，避免纵向长表翻页；下方详细表按出现次数降序，保留资料日期范围列，日期范围格式为 `YYYY（MM-DD ---> MM-DD）`，跨年时写为 `YYYY（MM-DD） ---> YYYY（MM-DD）`。
- metadata-only 股票资料如果已经进入 `资料索引.md` 或 `股票资料汇总.md`，不得只停留在 `80-raw-原始资料/Cubox/股票/extracted/`；必须同步在 `Wiki/10-股票投资/01-Cubox资料流/主题资料总结/` 下建立候选 wiki 页，并在同目录生成资料脑图。候选页状态使用 `status: inbox`，正文明确写“metadata-only / 未转写 / 待核验”。
- 完成股票资料整理前必须验证：`股票资料汇总.md` 能搜索到本轮新增/更新标题；`公司名出现频率总表.md` 已按最新标黄公司名重算，且表格不包含关系图/Canvas/资料脑图来源；本轮新增或更新的资料脑图都是合法 JSON。
