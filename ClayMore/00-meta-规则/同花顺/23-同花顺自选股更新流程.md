# 同花顺股票更新规则

本页是同花顺股票更新的唯一规则入口。解析、字段映射、代码归一化、Markdown 生成和校验细节由脚本负责，不在规则里重复维护。

## 触发条件

| 用户意图 | 执行命令 |
|---|---|
| 更新股票 / 更新我的股票 / 同步同花顺 | `python .\Tools-工具\update_ths_stocks.py` |
| 只更新自选股 / 同花顺自选股 | `python .\Tools-工具\update_ths_stocks.py --only self` |
| 只更新持仓 / 我的持仓 / 同花顺持仓板块 | `python .\Tools-工具\update_ths_stocks.py --only holdings` |
| 表格整理股票信息 / 输出股票 Markdown 汇总 | 先确保 `我的自选.md` 和 `我的持仓.md` 已更新，再更新 `Wiki/10-股票投资/02-股票研究流/我的股票信息.md` |
| 整理股票 / 整理产业链 / 股票资料整理出板块表 | 同步更新股票投资总控台、`板块优质股票速查表.md` 和 `Wiki/10-股票投资/板块优质股票速查表-看板.canvas` |

## 安全边界

- 只读本地同花顺缓存、名称表和“我的板块”文件，不修改同花顺目录。
- 不读取交易记录、资金流水、账号、密码、券商登录、银行卡等高敏信息。
- 不操作 `ClayMore-Private-Wiki/`。
- 股票和财务内容标注来源和不确定性。
- 自选股清单只表示观察列表；“我的持仓”来自同花顺自定义板块，不等同于券商真实持仓。

## 执行要求

1. 在 Obsidia 根目录运行脚本。
2. 交付前运行 `python .\Tools-工具\test_update_ths_stocks.py`。
3. 向用户报告自选股和持仓的记录数、名称缺失、价格/日期缺失、新增、移除。
4. 后续每次更新自选股和持仓，都必须以 Markdown 表格形式整理输出；`我的自选.md` 中的股票条目保留在“自选表”，`我的持仓.md` 中的股票条目保留在“持仓表”，`我的股票信息.md` 中的股票条目同步保留在“我的持仓”和“自选股”两张汇总表，不散写成普通列表。
5. 用户要求 Markdown 表格汇总时，优先更新已有的 `我的股票信息.md`；若不存在，可创建该页，至少包含更新摘要、我的持仓、自选股、待补充信息和相关页面。
6. 汇总页只整合脚本目标页已有字段，不补写行业、估值、仓位、成本、盈亏等缺源或高敏字段。
7. 如果脚本报错，修脚本或数据源问题；不要把脚本已经覆盖的解析细节补回规则页。
8. 用户说“整理资料”“整理股票”“整理产业链”且范围涉及股票、上市公司、板块、行业或产业链时，除了更新对应资料页，还必须同步维护 `Wiki/10-股票投资/股票投资总控台.md`、`板块优质股票速查表.md` 和 `Wiki/10-股票投资/板块优质股票速查表-看板.canvas`：表格按“主线 / 环节 / 优先级 / 公司 / 代码 / 资料热度 / 备注”整理；看板用“超大看板=板块分类、大看板=投资主线、内容看板=该主线下所有产业链环节汇总”的三层结构，不使用箭头连线。默认超大看板可按“科技成长板 / 能源或算电板 / 材料或化工板 / 消费金融周期板 / 待确认观察板 / ETF或工具板”归类；不要创建笼统的“其他归档/未分类”超大看板。总控台必须保留速查表和看板入口，作为股票投资目录的总入口索引。
9. 板块产业链看板的 A 股内容看板必须使用多字段 Markdown 表格：固定列为 `环节 / P / 公司/标的 / 代码 / 价 / 热 / 营 / 利 / PE`，每项数据必须单独成列，保证每列上下对齐；同一环节连续多只股票时，环节列只在第一行显示，后续同组行留空以减少重复。其中“价”表示同花顺本地记录价，“营/利”表示最近季度营收同比和归母净利润同比，省略 `%` 以减少横向占用。归档自选没有明确优先级时统一填 `P3`。ETF、基金、指数工具看板不要套用 A 股财务表，必须改用工具表：`分类 / 类型 / 标的 / 代码 / 价格或净值 / 日期`，同一分类连续多行时也只在第一行显示分类；数据来自同花顺原始自选股或 `我的股票信息.md`。不要在表格外使用普通 Markdown 横线分隔环节，避免 Obsidian 分隔线边距导致节点高度失真。内容看板宽度和高度必须按表格列数、最长字段和实际行数估算，不得使用固定大宽度；节点右侧不应留下大片空白，也不能出现滚动条或裁切。生成后校验 Canvas JSON 合法、节点数量非零、`x/y/width/height` 为 number，且内容看板不得超出所属大看板边界。
10. 重建或改版板块产业链看板时，不得让已有数据字段退化为空。A 股公司代码优先来自 `我的股票信息.md` 和 `A股公司名称库.csv`，价格优先来自同花顺原始自选股 `80-raw-原始资料/同花顺自选股/` 和 `我的股票信息.md`；ETF/基金/指数工具代码、价格或净值、日期优先来自同花顺原始自选股 `80-raw-原始资料/同花顺自选股/` 和 `我的股票信息.md`；资料热度来自 `公司名出现频率总表.md`；A 股营收同比、归母净利润同比和 PE(TTM) 必须沿用原口径：东方财富数据中心 `RPT_LICO_FN_CPD` 的 `YSTZ/SJLTZ` 与东方财富估值分析 `RPT_VALUEANALYSIS_DET` 的 `PE_TTM`。公司类标的不得因格式转换、字段拆分或正则不匹配丢失代码、价格、热度、营收、利润或 PE；工具类标的不得显示无意义的营/利/PE 空列；生成后必须校验除“同组重复隐藏列”外的数据字段没有空值。
11. 超大看板必须统一左对齐并使用固定纵向间距：上一个超大看板底部到下一个超大看板顶部默认 `180` Canvas 单位；调整超大看板位置时必须同步平移其内部大看板和内容节点，生成后校验所有超大看板间距一致。
12. 改版或重建板块产业链看板时，只校验 JSON 几何边界不够；新增字段、加宽列、替换长公司名或调整表格格式后，必须按 Obsidian 实际渲染宽度重新估算内容节点宽度，并同步重排所属大看板和超大看板。生成后必须做视觉缓冲重叠校验：内容节点之间、大看板之间至少保留可读间距，建议按不小于 `80` Canvas 单位的缓冲检查；若同一超大看板内有左右两列或多列分组，必须显式按语义归组后重排，不能只依赖原坐标包含关系判断归属。

## 不确定性声明

每次输出股票清单时确认目标页中已有来源和不确定性说明：

> 来源为本机同花顺缓存和自定义板块；价格和日期是本地记录值，可能不是实时行情。该清单仅用于个人观察和 Wiki 记录。
