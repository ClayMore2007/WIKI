## 默认流程

1. 先做快速增量索引：扫描 `80-raw-原始资料/待整理/` 和外部同步目录的文件名、frontmatter、URL、标题、大小、修改时间；与稳定 raw、已有 wiki 页面、索引、汇总页和整理日志对照，标记新增、变化、已处理和跳过项。
2. 只处理新增、变化或已提取但未沉淀 wiki 的增量；已处理且无变化的资料不重复复制、转写或沉淀。
3. 外部同步目录保持原貌，不移动、不重命名、不删除。
4. 先保留 raw/source，再沉淀 wiki 页面；用户说“更新资料”默认就是完整流程，不等同于只提取。
5. 资料包含图片、截图、图表或封面时，整理产物必须附上相关图片；附件放入 `90-assets-附件/` 或沿用已有附件路径。
6. 图片中包含文字、图表、清单、数据或结论时，必须同步整理图片内容，并把图中主张、图中数据/清单和待核验点写入 raw、wiki 或整理报告；高风险内容标为“图片声称 / 待核验”。
7. 对已沉淀到独立 wiki 页的资料，默认同步生成 Advanced Canvas 兼容的资料脑图，放在对应 wiki 页面同目录，命名为 `原页面标题-资料脑图.canvas`；单篇资料不再默认生成 `关系图.canvas`、`候选关系图.canvas` 或 `思维导图.canvas`。
8. 过程、异常、候选合并、用户确认事项写入 `00-log-整理日志/`。
9. 新整理产物必须有整理日期；来源发布日期、收藏日期或文件日期能确认就记录，补不上时写“来源日期未知”，不为补日期卡住整理。
10. 主知识页放在 `Wiki/`，只放稳定知识、索引、判断、待核验问题和行动。
11. `_notes_template.md` 只是提取脚本模板，不能当作已整理内容；若仍含 `TODO:`，必须在报告和索引中标为“已提取但未编译”，并继续编译到 wiki 或说明阻塞原因。

## 日常笔记

- 用户消息以“笔记”开头时，默认保存到 `75-笔记/00-收件箱/`。
- 记笔记优先快记：使用固定收件箱模板直接保存，不重复展开专项规则，不读取相关 wiki 页面，不做行情、来源或分类核验；笔记只保留原文和必要关联。
- 用户笔记涉及股票名时，先用 `Wiki/10-股票投资/02-股票研究流/基础数据/A股公司名称库.csv` 或同目录 JSON 做名称规范校验；这只用于修正标题和汇总中的股票名称，不等同于行情、来源、分类或投资结论核验。若用户输入疑似错字且本地库有明确匹配，笔记标题和汇总使用校验后的规范名称，并在正文保留原始输入和校验说明；若无法明确匹配，保留原文并标注“股票名待确认”。
- 保存笔记后，自动把原文按简要分类追加到 `75-笔记/10-已整理/笔记汇总.md`，条目后标注记录日期；同时更新 `75-笔记/笔记总览脑图.canvas`。以后笔记总览脑图默认且必须按类型汇总：每个类型只保留一个摘要文本框，框内按记录日期升序列出该类型笔记的核心内容和原文链接；入口页、待确认等辅助区也同样合并为摘要文本框。版式采用左侧中心节点、右侧类型框纵向排列、箭头从中心发散；所有节点都使用普通摘要文本，框体尺寸要能容纳内容，避免滚动条；不要为每条笔记或每个入口创建独立节点，不要直接使用会展开全文预览的 file 节点，也不要把 frontmatter、可能关联、整理状态或关联页面内容搬进脑图。
- 用户提到“复盘”且没有指定其他去向时，默认保存到 `75-笔记/20-每日复盘/YYYY/YYYY-MM-DD.md`，并同步追加到 `75-笔记/20-每日复盘/复盘汇总.md`；明确说“周复盘”时更新 `003-周复盘.md`。
- 用户说“整理笔记”时，从 `75-笔记/00-收件箱/` 整理到 wiki，优先更新已有页面；过程写入 `00-log-整理日志/`。
- 用户说“整理笔记”“更新股票”“查行情”或要求进入决策页时，再展开对应规则并做详细核验。

## 快捷脚本

- 股票更新优先使用 Obsidia 工程下的脚本：`python .\Tools-工具\update_ths_stocks.py`。
- 泛指“更新股票 / 更新我的股票 / 同步同花顺”时，默认同时更新自选股和我的持仓。
- 明确只更新自选股时使用 `python .\Tools-工具\update_ths_stocks.py --only self`。
- 明确只更新持仓时使用 `python .\Tools-工具\update_ths_stocks.py --only holdings`。
- 脚本只读本机同花顺缓存、名称表和“我的板块”文件，不读取券商真实交易记录。
- 用户要求把股票信息整理成 Markdown 表格时，优先更新 `Wiki/10-股票投资/02-股票研究流/我的股票信息.md`，作为 `我的持仓` 和 `我的自选` 的汇总查看页。
- 用户说“整理资料”“整理股票”“整理产业链”且内容涉及股票、上市公司、板块、行业或产业链时，同步更新 `Wiki/10-股票投资/股票投资总控台.md`、`Wiki/10-股票投资/02-股票研究流/板块优质股票速查表.md` 和 `Wiki/10-股票投资/板块优质股票速查表-看板.canvas`；字段、看板层级、数据回填和校验口径以 [[00-meta-规则/同花顺/23-同花顺自选股更新流程]] 为准。
- 改版或重建股票看板时，不得让已有数据字段退化为空；A 股公司代码、价格、资料热度、营收、利润和 PE 必须按 [[00-meta-规则/同花顺/23-同花顺自选股更新流程]] 的原来源回填；ETF/基金/指数工具代码、价格或净值、日期从同花顺原始自选股和 `我的股票信息.md` 回填；工具类标的不要显示无意义的营/利/PE 空列，生成后必须校验除“同组重复隐藏列”外的数据字段没有空值。
- 股票看板内容节点和所属大看板必须按实际表格渲染宽高收紧，不得使用固定大宽度；右侧不应留下大片空白，也不能裁切内容、出现滚动条或与相邻节点重叠；字段增减后必须重新做视觉缓冲重叠校验。
- 股票看板的超大看板必须统一左对齐，纵向间距固定为 `180` Canvas 单位；移动超大看板时同步移动内部大看板和内容节点。

## 编译层判断

| 输入 | 输出 |
|---|---|
| 单条来源 | raw 来源笔记 |
| 一组来源入口 | 索引页 |
| 3 个以上同主题来源 | 主题页 |
| 反复出现的判断 | 问题页 |
| 影响行动的选择 | 决策页 |
| 整理过程和异常 | 整理日志 |

股票资料的新增、更新、候选页、资料正文、公司名标黄或 raw 索引发生变化时，必须同步检查 `Wiki/10-股票投资/01-Cubox资料流/股票资料汇总.md` 和 `Wiki/10-股票投资/01-Cubox资料流/公司名出现频率总表.md`。

## 展开正文的条件

第一轮只读文件名、frontmatter、URL、标题、大小和修改时间。只有以下情况读正文：

- `tags` 为空、无效或无法映射。
- 标签与标题/内容疑似冲突。
- 涉及股票、财务、健康、法律、账号、身份、保险或隐私。
- 需要提取长期知识，而不是只做 raw 归档。

## 整理报告最小结构

| 模块 | 内容 |
|---|---|
| 本次范围 | 扫描目录、文件数量 |
| 分类审计表 | 原文件、原始标签、分类、冲突说明 |
| 处理追踪表 | 原文件、raw 副本、wiki 页面、状态 |
| 处理结果 | raw 数量、更新页面、跳过文件 |
| 注意事项 | 不确定、敏感内容、待核验信息 |
| 待确认事项 | 需要用户判断的分类、合并、迁移或删除 |
| 日期信息 | 整理日期必填；来源发布日期、收藏日期或文件日期能确认就写，补不上写“来源日期未知” |

状态字段固定为：未处理 / 已复制 raw / 已提取 raw / 已沉淀 wiki / 已跳过。
